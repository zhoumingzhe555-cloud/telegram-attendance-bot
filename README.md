## AI室使用记录

- 群内发送 `AI室记录`（也支持繁体）或 `/airecords`，查看本群当前清空周期的使用明细。
- 显示人员、用户ID、房间、进入时间、离开时间和使用时长；未离开显示“使用中”。
- 发送房间名称开始记录，发送“回”或“下班”结束；换房结束上一段并开始下一段，重复登记同一房间不拆分使用记录。
- 各群独立，跨午夜不中断，以本群 `/setreset` 配置为界，默认每天 05:05 随考勤数据清空，不建立独立历史库。
- 查询过长自动发送 TXT，服务器端不保存该导出文件。已经发送到 Telegram 的消息或文件不会随服务器清空自动撤回。
- 兼容原有打卡数据；新增记录带房间标记，后续删除房间配置仍可查询本轮记录。升级前已删除的自定义房间没有此标记，无法自动识别。


## 按小组统计离岗及上班打卡

默认名单：渣男组12人、金花组12人、杨逍组12人、徐江组11人，共47人。

仅在需要启用的群内，由管理员发送 `/initgroups` 导入名单并开启统计；重复执行不会覆盖人员调整。昵称不用于自动认人，管理员回复真实成员消息发送 `/setgroup 金花组 金圣` 将名单姓名绑定到 Telegram ID。修改昵称不影响已绑定成员。未绑定的打卡和离岗会显示为未分组，避免丢计或误认。

- `/groups`：查看名单及绑定状态。
- 回复成员消息 `/setgroup 组名 名单姓名`：绑定、新增或调组；同名已绑定到他人时拒绝覆盖。
- 不回复消息 `/setgroup 组名 姓名`：添加待绑定成员或调整现有成员组别。
- 回复成员消息 `/delmember`，或 `/delmember 姓名`：删除成员。
- `/hourlyreport`：查看当前小时实时统计，不影响自动发送。

自动报表发到当前群，遵循各群 `/setstart` 与 `/setend` 的北京时间设置：默认09:55上班、次日02:00下班。上班时发送各组已打卡人数/名单总人数，每个ID仅计一次；统计从最近的考勤清空时间（默认05:05）起的上班打卡，支持提前打卡。仅在上班时刻所在的一分钟发送该快照，之后打卡不会改写已发送消息；停机错过该分钟不补发晨报。

工作时段每整点汇总上一时段的wc小、wc大、抽烟合计；例如“金花组：金圣1、吉祥2，合计3次”。名单零次人员也显示。默认10:00首报覆盖09:55—10:00；02:00发送01:00—02:00最后一报，随后停止，直到下一次上班。调度每30秒检查，发送可能比整点晚约30秒。非整点下班时汇总最后一个不足一小时的时段。

事件按群和消息ID去重；已发生的事件保留当时组别，之后调组/删除不抹去这些次数。未绑定事件可在发送前通过ID绑定归组。小时统计独立于每日CSV清空，05:05清空不会截断小时；发送成功后删除该时段离岗事件，异常情况下最多保留24小时。人数统计的打卡记录最多保留24小时；名单、绑定和发送进度长期保留，不受每日清空影响。

新统计从启用后开始，不自动补录旧CSV。SQLite文件为 `data/hourly_groups.sqlite3`；生产环境应将应用的data目录挂载持久卷，否则重新部署可能丢失运行期名单修改和绑定。支持同一实例重启恢复发送进度；发送成功但进度写入前进程崩溃时可能重发，不支持多个机器人进程共同负责同一群。停机错过多个小时只补最近时段，不补全天。

本地验证：`python tests/test_hourly_groups.py`。
